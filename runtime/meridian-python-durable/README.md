# Prism durable Schema registry runtime

Version 2.0.0 selects `postgresql-postgis-s3-durable-schema-registry`, Python3.12.11/cp312/Linux amd64. The legacy directory, runtime1.1.0 and exact Lattice0.3.0/0.1.0 consumer lock remain independent and unchanged. These bases are not interchangeable.

The hash lock selects Core1.1.0, Semantics2.1.0, PostgreSQL2.3.1, Query1.0.3, Evidence1.0.2, Projection1.0.3, Streaming1.0.1, ObjectCommon1.0.3, S3 1.0.4 and Pydantic2.13.4. Streaming is a library dependency; this profile selects no streaming adapter or engine. The public overlay verifies Observability1.0.3 and OTel1.44.0 (semantic conventions0.65b0). `consumer-lock.json` records all overlay coordinates/hashes. It contains no private domain wheel or source.

`bindings.py` is platform-owned and integrity-checked with the image inventory. A domain calls `create_bindings` after verifying the projected descriptor. It receives public Meridian and, when `MERIDIAN_METADATA_BINDING` selects an explicit metadata-registry layout, a public SchemaAPI factory. The factory requires the current authenticated OperationContext with tenant, principal and deadline; every invocation creates a separate repository. It reads through the public PostgreSQLSchemaRepository using fresh projected credentials and authenticated TLS. Core retains its immutable startup snapshot for static physical resources. Dynamic metadata reads go to SchemaAPI with exact inner SchemaDocument pins. No global dynamic registry refresh or tenant cache is introduced.

Configuration and physical resource selection belong to Foundations. Service code imports no Adapter. The platform resolver accepts only absolute projected-file references, including Kubernetes atomic symlink rotation, rejects non-regular/empty/oversize files, and never logs credentials. Construction opens no connection. Neither startup nor publication executes DDL. Missing metadata migrations fail closed through the public adapter/repository. Physical migration is a separate platform job and is not executed by these gates.

The provider bundle, ResourceDefinition, Core SchemaDefinition wrapper and inner Semantics SchemaDocument have distinct fingerprints. Metadata references pin the inner document. The metadata-registry physical layout pins the Core wrapper. Publication and schema validation never substitute either for another.

Build and inspect with the existing hash-locked Dockerfile and `check_image.py`. `check_consumers.py` installs the exact public overlay without network and checks public native APIs, installed inventory and independent Schema fingerprints as a non-root user on a read-only root. These are packaging gates. Actual Prism wheel/image gates are owned by the service releases. Constructs1.4.0 has a separately reported put@2.0.0/atomic-evidence declaration defect; this profile does not claim physical closure, migration or live-platform acceptance.
